# 虚拟方向盘 · demo

手机陀螺仪 + 加速度计 → 局域网 UDP → 电脑端命令行，**每 0.1 秒打印一次处理后的转向值**。

这一版是**完整可用的 demo**：数据预处理 + 写进虚拟 Xbox 360 手柄，游戏里直接当手柄用。

- 手机端：读陀螺仪/加速度计/姿态 → UDP 发出；主界面是 Xbox 布局的 14 个按键（含十字方向键，开始/停止、回正、重新校准在正中间），支持手动横竖屏、深色模式、中/繁/英三语；参数（IP、角度范围、转向轴、滤波、语言）都在设置页。
- 电脑端：投影到旋转轴（可自动识别，手机斜着贴也行）→ 自动校准零偏 → 死区 → 一阶低通平滑 → 积分成转角 → 自动回正 → 限幅到 ±90°…±900°（单边角度，可无级设置） → 映射成 **±32767**，同时识别按键的按下/松开；过程中用 **ZUPT（静止零偏重估）+ 手机上传的姿态四元数慢修正** 抑制积分漂移；最后把这些值写进 **虚拟 Xbox 手柄**（vgamepad + ViGEmBus）：转向 → 左摇杆 X，14 个键 → ABXY/LB/RB/LT/RT/L3/L4 + 十字方向键。

```
┌────────────────────┐   UDP，约 200Hz 104 字节  ┌──────────────────────────┐
│ 手机 uni-app x      │ ───────────────────────▶ │ 电脑 python main.py        │
│ 陀螺仪+加速度+姿态    │   192.168.x.x:8888       │ vwheel/ 滤波/映射/虚拟手柄  │
│ +按键               │                          │ tools/ 自测脚本            │
└────────────────────┘                          └─────────────┬────────────┘
                                                              │ Xbox 360 手柄
                                                    ┌─────────▼─────────┐
                                                    │ ViGEmBus 虚拟手柄   │
                                                    │ → 游戏/模拟器       │
                                                    └───────────────────┘
```

## 最快验证顺序

1. **先验电脑端**（不用手机）：
   ```bash
   cd "virtual wheel desktop"
   python main.py          # 终端 A
   python tools/simulate.py    # 终端 B
   ```
   终端 A 先显示 1 秒「校准中…」，再花一秒左右识别旋转轴（假数据默认模拟手机倾斜 30° 安装），
   然后每 0.1 秒刷一行：
   ```
   [    3.0s]  49.8pkt/s 丢包=0    ±540° ----------#----------  角度=  +57.3°  值= +3477  角速度= +1.00  键=-  姿态=ok e= +0.4°  t=+   1.52s
   ```
   想对比「自动轴 vs 固定轴」：`python tools/simulate.py --tilt 30 --axis z`，同样的转动只会得到 0.87 倍的角度。
2. **再上手机**：HBuilderX 打开 `virtual wheel andriod`，运行到 Android 真机（**不要用浏览器预览**）。进「设置」填 `main.py` 启动时打印的局域网 IP，保存后回主界面点「开始」。
3. 电脑端开始刷真实数据，手机上的「已发送」包数同时上涨 —— 链路通了。

## 转向值是怎么算出来的

```
gyro(rad/s) ──┬─ 投影到旋转轴：rate_raw = gx·nx + gy·ny + gz·nz
              │   （nx,ny,nz = 0/1 时就是直接取某一轴；自动模式下由 PCA 估出来）
              ├─ 前 1 秒静止样本求均值 = 零偏 bias（三维向量）
              │
              └─ rate = rate_raw - bias·n
                    │  |rate| < deadzone → 0        （死区，防漂移）
                    │  r = r + (1-smoothing)*(rate-r)（一阶低通）
                    ▼
             angle += r * dt * 180/π               （积分成角度，度）
                    │  angle -= angle * selfCenter * dt（自动回正，0 = 关）
                    ▼
             angle 限幅到 ±rangeDeg
                    ▼
             value = angle / rangeDeg * 32767     （±32767，四舍五入取整）
```

- `dt` 用手机端随包发来的毫秒时间戳计算，所以手机和电脑的时钟不用对齐。
- 断流超过 0.5 秒时不会把空档时间累加进角度，只重新对齐时间戳。
- `rangeDeg` 是**单边**角度：`90` 就是 ±90°（总量程 180°），`900` 是 ±900°（总量程 1800°），
  中间 90..900 任意整数都能用（手机端设置页是无级调节），不需要改算法。
- 角度范围越小，同一个 `angle` 越早被限幅，因此更容易打满 ±32767（转向更"灵敏"）；
  范围越大越接近真车的多圈方向盘，但也更容易被漂移带偏。

## 防漂：ZUPT + 姿态慢修正

陀螺仪积分一定会漂。这里不做「重新发明姿态融合」，而是用两种成本很低的手段压住漂移：

| 手段 | 触发条件 | 作用 | 代价 |
|------|----------|------|------|
| **ZUPT**（零速修正） | 连续 0.6 秒角速度几乎不变（`\|ω-零偏\| < 0.04 rad/s`） | 把当前读数当新零偏，每帧挪 30% 过去 | 无（方向盘本来就常回正不动） |
| **姿态慢修正** | 手机上传的姿态四元数可用，且 `\|e\| ≤ 45°`、转速 ≤ 15°/s | 每帧把积分角往姿态角拽 `0.05·e·dt`（时间常数约 20 秒），残差记进零偏 | 用的是系统融合结果，只在慢速时参考，不影响手感 |

- 姿态四元数来自 Android 的 `TYPE_ROTATION_VECTOR`（系统用加速度计+陀螺仪+磁力计融合，**不漂但延迟 50~150ms**），
  由 `vw-udp` 插件用 `SensorManager` 采集后随样本包发出，页面不需要额外处理。
- 转得快时不修正，是因为融合器的延迟会让「参考角度」落后真实角度，此时拽它反而制造滞后。
- 车里磁环境差（EPS 电机、大电流）时姿态参考本身会被带偏，看到 `[!] 姿态与积分相差 …°` 就加 `--no-att`，
  只保留 ZUPT（`--no-zupt` 则相反，两个都能单独关）。
- 想再进一步可以换成 1 维卡尔曼（状态 = [角度, 零偏]，观测量 = 姿态角），大约 30 行；当前 PI 观测器已经够 demo 用。

## 手机斜着贴也能用：旋转轴自动识别

陀螺仪给的是**机体坐标系**的角速度（绕手机自己的三个轴转得多快），和整台设备在空间里怎么倾斜
（重力朝哪）**没有关系** —— 所以真车方向盘是斜的、盘面是歪的，只要手机固定在上面，读数方向就不变。

要担心的是另一件事：**方向盘的旋转轴，在手机坐标系里未必是 x / y / z 之一**。
如果手机相对转向柱装了 30°，真实轴就是 `n=(0, sin30°, cos30°)=(0, 0.5, 0.866)`，
这时只取 `gz` 只能拿到 `cos30°=0.87` 倍，左右打方向还会串到别的轴。

物理上，轮子绕单位轴 `n` 以 `Ω` 转时陀螺仪读数正好是 `ω = Ω·n`，所以

```
Ω = ω · n = gx·nx + gy·ny + gz·nz
```

只要知道 `n`，投影一下就是**真实**角速度。于是转向轴有四档：

| 设置 | 含义 |
|------|------|
| `X` / `Y` / `Z` | 手动指定，要求机身轴和转向柱基本平行（贴法很正时最省事、最稳） |
| `自动`（默认） | 不假设贴法：开始后把手机当方向盘**慢慢左右各打一次**，电脑端用这批角速度的协方差主方向（PCA，幂迭代）估出 `n`，之后一直用它投影 |

自动模式的判定：`Σ|ω|²` 能量够大（真的转起来了）+ 主方向占总能量 75% 以上（转得够一致），
至少 24 帧；攒了 6 秒还不达标就用现有样本硬锁。锁定瞬间电脑端会打印：

```
           [ok] 旋转轴已锁定 n=(-0.11, +0.49, +0.87)  一致度=1.00（1.00 = 转得很干净）
```

锁定那一刻会把角度清零（之前那段是在"摸索"，不是有效转角）。
换了转向轴设置或者点「重新校准」，会重新开始识别。

自测（`python -m vwheel.steering`）里有一组倾斜 30° 的对照：手动 `Z` 只能得到 `0.87×`，自动模式则精确还原 57.30°/秒。

## 协议（两端必须一致，小端）

### 样本包 104 字节 `<ii7dii4d>`

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | int32 | type | 固定 1 |
| 4 | int32 | seq | 包序号，从 1 递增，电脑端用它算丢包 |
| 8 | float64 | gx | 陀螺仪 x 轴角速度 rad/s |
| 16 | float64 | gy | y 轴 |
| 24 | float64 | gz | z 轴 |
| 32 | float64 | ax | 加速度计 x 轴（单位 g） |
| 40 | float64 | ay | y 轴 |
| 48 | float64 | az | z 轴（手机平放时 ≈ 1.0） |
| 56 | float64 | t | 采样时刻，Unix epoch 毫秒 |
| 64 | int32 | btnMask | 按键位图，见下表 |
| 68 | int32 | flags | bit0=角度归零，bit1=重新校准 |
| 72 | float64 | qx | 姿态四元数 x（Android `TYPE_ROTATION_VECTOR`） |
| 80 | float64 | qy | 姿态四元数 y |
| 88 | float64 | qz | 姿态四元数 z |
| 96 | float64 | qw | 姿态四元数 w；**四个都为 0 = 手机没有姿态数据** |

### 配置包 36 字节 `<iii3d>`

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | int32 | type | 固定 2 |
| 4 | int32 | rangeDeg | 单边角度范围 90..900（`90` = ±90°，`900` = ±900°） |
| 8 | int32 | axis | 转向轴 0=X 1=Y 2=Z 3=自动识别 |
| 12 | float64 | deadzone | 死区 rad/s |
| 20 | float64 | smoothing | 平滑 0~0.95 |
| 28 | float64 | selfCenter | 自动回正速率 1/秒，0 = 关 |

### 按键位图

| 键 | code | 位 |
|----|------|----|
| A | 1 | `1<<0` |
| B | 2 | `1<<1` |
| X | 3 | `1<<2` |
| Y | 4 | `1<<3` |
| LB | 5 | `1<<4` |
| RB | 6 | `1<<5` |
| LT | 7 | `1<<6` |
| RT | 8 | `1<<7` |
| L3（左摇杆按下） | 9 | `1<<8` |
| L4（右摇杆按下） | 10 | `1<<9` |
| ↑（方向键上） | 11 | `1<<10` |
| ↓（方向键下） | 12 | `1<<11` |
| ←（方向键左） | 13 | `1<<12` |
| →（方向键右） | 14 | `1<<13` |

按键是**状态**（每个样本包都带当前位图）而不是「按下/松开事件包」：丢一包，下一包就自动纠正，
电脑端用前后两包的位图 diff 算出边沿，打印 `↓ 按下 A` / `↑ 松开 A`。

## 最后一步：写进虚拟 Xbox 手柄

电脑端不自己造驱动，而是用 **vgamepad + ViGEmBus** 挂一个「Xbox 360 Controller for Windows」，
游戏/模拟器会把它当成真手柄。

```bash
pip install -r requirements.txt          # Python 包（vgamepad）
# 再装 ViGEmBus 驱动：https://github.com/nefarius/ViGEmBus/releases
python -m vwheel.gamepad --real          # 验证：摇杆扫一遍、按一下 A
python main.py                           # 正常跑，横幅里会打印「手柄输出：…」
```

| 手机端 | 虚拟手柄 |
|--------|----------|
| 转向值 -32767..32767 | 左摇杆 X（`--stick ly/rx/ry` 可换轴） |
| A / B / X / Y | A / B / X / Y |
| LB / RB | 肩键 |
| LT / RT | 左/右**模拟扳机**（0 或 1 满行程） |
| L3 / L4 | 左/右摇杆按下 |
| ↑ / ↓ / ← / → | 十字键上/下/左/右 |

三个安全行为：

- **每包更新**：约 200Hz 写一次手柄，手感跟得上；
- **断流回中**：超过 1 秒收不到包，方向自动回中、按键全松（比卡在打死安全）；
- **退出 reset**：Ctrl+C 时 `pad.reset()`，不会给下一个程序留一个卡住的手柄。

没装 vgamepad / 驱动没起时，`main.py` 只在横幅里提示一句，收数据、打印、自测照旧能跑（`--no-gamepad` 可以显式关掉）。

## 还没有做的（demo 范围外）

- 扳机行程：现在 LT/RT 是 0/1，没有按压力度（手机屏幕也拿不到力度，除非用 3D Touch 类传感器）。
- 力回馈：方向盘不会自己抖/回弹，只能靠游戏内的 FFBA 或不做。
- 时钟对齐：`t` 是手机 `Date.now()`，没和电脑端对齐，只用于算 `dt`。
- 加密/重连：纯局域网明文，没有握手和重连。
