# 电脑端 —— UDP 接收 + 转向值预处理 + 虚拟 Xbox 手柄

监听 UDP 端口，把手机发来的传感器数据/按键/配置解析出来，**每 0.1 秒在命令行打印一行**，
同时把这些值**写进一个虚拟 Xbox 360 手柄**（vgamepad + ViGEmBus），游戏里直接就能用。

处理链路（`vwheel/steering.py`）：

```
前 1 秒静止样本 → 零偏 bias
rate = raw - bias
  ├─ |rate| < deadzone → 0              死区，静止时不漂
  ├─ r += (1-smoothing)*(rate-r)        一阶低通
  └─ angle += r * dt * 180/π            积分成角度（dt 来自手机时间戳）
angle -= angle * selfCenter * dt        自动回正（0 = 关）
angle 限幅到 ±rangeDeg（单边 90..900，可无级设置）
value = round(angle / rangeDeg * 32767) → ±32767
```

## 跑起来

```bash
# 1) 先看本机局域网 IP（main.py 启动时也会自己提示）
ipconfig

# 2) 装依赖（只做一次）
pip install -r requirements.txt

# 3) 启动接收端（默认监听 0.0.0.0:8888，每 0.1 秒打印一次，默认 ±540° 轴 Z）
python main.py

# 常用参数
python main.py --port 9000
python main.py -i 0.05             # 打印更密
python main.py --range 90          # ±90° 模式
python main.py --range 720         # ±720°，中间任意值都行（90..900）
python main.py --axis x            # 换成 x 轴
python main.py --axis auto         # 自动识别旋转轴（手机斜着贴也不用改设置）
python main.py --deadzone 0.05 --smoothing 0.5 --self-center 0.8
python main.py --no-att            # 关掉姿态慢修正（车内磁干扰很严重时用）
python main.py --no-zupt           # 关掉静止零偏重估（一般不用关）
python main.py --no-gamepad        # 只打印，不写虚拟手柄
python main.py --invert            # 方向反了（打左变打右）就加这个
python main.py --gain 1.4          # 转向增益：<1 更钝，>1 更容易打满
python main.py --stick ly          # 转向换到左摇杆 Y（默认 lx），可选 lx/ly/rx/ry
python main.py --raw               # 状态行带上原始三轴角速度和「轴外比」（查角度偏小用）

# 只算一遍自测（不需要网络）
python -m vwheel.steering
# 只测手柄输出（假后端，不需要驱动）
python -m vwheel.gamepad
# 真机测手柄（需要 vgamepad + ViGEmBus）
python -m vwheel.gamepad --real
```


启动后的前 1 秒会显示「校准中…（手机保持静止 1 秒）」，这 1 秒的样本用来算零偏，不积分。
手机端如果下发了配置包，会打印一行 `[cfg] 配置更新：±90° 轴=自动 死区=0.020 平滑=0.30 回正=0.00`，
之后的 `--range/--axis/...` 以手机端为准。

`姿态=ok e=+0.4°` 是防漂机制的工作状态：`ok` 表示拿到了手机上传的姿态四元数，`e` 是「姿态算出来的角度」和
「陀螺仪积分出来的角度」的差（正常时在 1~5° 内摆动，超过 45° 会暂停修正并在下面打一行 `[!]`）。
手机没有姿态数据（或用了 `--no-att`）时显示 `姿态=-`，此时完全靠陀螺仪积分 + ZUPT。

### 转向轴 = 自动 时多看一行

手机端默认下发 `axis=3`（自动）。这时校准结束后还要「识别旋转轴」：

```
[    3.3s]  49.6pkt/s 丢包=0    ±540° 识别旋转轴…请慢慢左右各打一次方向（已   3 帧，能量   0.7）  键=-  t=+   1.07s
           [ok] 旋转轴已锁定 n=(-0.11, +0.49, +0.87)  一致度=1.00（1.00 = 转得很干净）
```

看到 `[ok] 旋转轴已锁定` 之后才会出角度，锁定那一刻角度清零。调整手机的安装角度（比如塞进方向盘套里斜了 30°）也照样准，
因为 `n` 就是实测出来的旋转轴方向。想固定用某个轴就 `python main.py --axis z`，或手机设置页里选 X/Y/Z。

### 防漂：ZUPT + 姿态慢修正

陀螺仪积分一定会漂（手机便宜陀螺的零偏随温度、时间变）。这里有两层保护，默认都开着：

1. **ZUPT（静止零偏重估）**：连续 0.6 秒角速度几乎不变（抖动量 < 0.04 rad/s），就把当前读数当成新的零偏，
   慢慢（每帧 30%）挪过去。方向盘大部分时间是回正不动的，所以这条能一直小幅纠偏。
   触发时打印 `[zupt] 静止零偏重估 #N：当前零偏=+0.00012 rad/s`（最多 3 秒一次）。
2. **姿态慢修正**：手机把 Android 的 `TYPE_ROTATION_VECTOR`（系统融合出来的姿态四元数，加速度计+陀螺仪+磁力计）
   一起发上来。它不漂但延迟大（50~150ms），所以**只用来当慢参考**：每帧把积分结果往姿态结果拽一点点
   （比例增益 0.05，相当于 20 秒时间常数），同时把残差记进零偏估计。
   转得快的时候（> 15°/s）或两者差太多（> 45°）就暂停修正——那时融合器的延迟会让参考失真，
   或者干脆是被磁干扰带偏了。

结果就是：手感仍然由陀螺仪决定（无额外延迟），但慢慢漂掉的部分会被拉回来。
车里磁环境很差（EPS 电机、大电流）时如果看到 `[!] 姿态与积分相差 …°`，加 `--no-att` 只留 ZUPT 更稳。

## 写进虚拟 Xbox 手柄（vgamepad + ViGEmBus）

预处理完的 `值`（-32767..32767）和按键位图会直接写进一个**虚拟 Xbox 360 手柄**，游戏把它当成真的手柄。

### 装依赖（只做一次）

```bash
pip install -r requirements.txt
```

还要装 **ViGEmBus 驱动**（`https://github.com/nefarius/ViGEmBus/releases` 里的 `ViGEmBus_Setup_*.exe`，一路下一步）。
装完可以用 `Get-Service ViGEmBus` 看服务是不是 `Running`。

验证：

```bash
python -m vwheel.gamepad            # 用假后端验证映射逻辑，不需要驱动
python -m vwheel.gamepad --real     # 真的建一个虚拟手柄，摇杆扫一遍 + 按 A/LT
```

`--real` 跑的时候打开 `https://hardwaretester.com/gamepad`（或 Windows 的「设置 → 蓝牙和其他设备 → 设备和打印机」），
能看到一个 **Xbox 360 Controller for Windows**，左摇杆跟着扫、A 键闪一下，就说明链路通了。

### 映射表

| 手机端 | 手柄 |
|--------|------|
| 转向值 -32767..32767 | **左摇杆 X 轴**（`--stick ly/rx/ry` 可换，`--invert` 反打） |
| A / B / X / Y | A / B / X / Y |
| LB / RB | 左/右肩键 |
| LT / RT | 左/右**模拟扳机**（按下给满行程 1.0，松开 0.0） |
| L3 / L4 | 左/右摇杆按下 |
| ↑ / ↓ / ← / →（方向键） | 十字键上/下/左/右（code 11~14，位 `1<<10` ~ `1<<13`） |

几个行为细节：

- 按键是**状态位图**，靠前后两包 diff 出边沿，所以丢一两包也不会卡键。
- 手柄**每收到一个样本包就更新一次**（约 200Hz），比 0.1 秒的打印快得多，手感才跟得上。
- **断流保护**：超过 1 秒没收到包，自动把方向回中、所有键松开（车还在跑的话，自己回正比卡在打死安全）。
- **退出时 reset**：Ctrl+C 会把摇杆回中并松键，避免下一个程序拿到一个「卡住」的手柄。
- 驱动掉了 / 手柄创建失败时，只打印 `手柄输出：没装 vgamepad…`，收数据、打印、自测全都不受影响。

### 在游戏里用

1. 先跑 `python main.py`，看到 `手柄输出：虚拟 Xbox 360 手柄已连接`；
2. 再开游戏（Steam 里玩的建议关掉 Steam Input 对这个游戏的覆盖，否则可能被再映射一层）；
3. 游戏的控制设置里选 XInput / Xbox 360 手柄，转向绑到左摇杆 X 轴。

方向反了加 `--invert`；打不满（比如 ±540° 时永远到不了底）加 `--gain 1.4`，或者手机设置页把角度范围调小
（无级，90..900 任意值，调成 ±360° 就比 ±540° 好转得多）。

## 没手机也能自测

另开一个终端，跑假数据发送器（协议和手机端完全一样，默认 50Hz，加 `--hz 200` 可模拟 200Hz 高频；还会模拟按键和回正/校准）：

```bash
python tools/simulate.py            # 默认发到 127.0.0.1:8888，并模拟手机倾斜 30° 安装
python tools/simulate.py --port 9000
python tools/simulate.py --tilt 0   # 假装手机和转向柱完全对齐
python tools/simulate.py --tilt 30 --axis z   # 对照：固定 z 轴只能拿到 cos30° 倍的角度
python tools/simulate.py --att-bias 0.02      # 给陀螺仪注入 0.02 rad/s 假零偏，验证姿态慢修正
python tools/simulate.py --no-quat            # 四元数发全 0，验证退化成纯陀螺积分
```

它会：先发一包配置 → 静止 1.5 秒（给电脑端做零偏校准）→ 绕倾斜 30° 的轴在 ±1.2 rad/s 之间摆动
→ 2~3 秒按 A、4~5 秒按 LB+RT、7~8 秒按 X+Y+L3、9~10 秒按 D-pad 的 ↑+→ → 第 10 秒发一次「回正」
→ 15.9~17.4 秒停住（给「重新校准」用）→ 第 16 秒发一次「重新校准」。
四元数是用实际 `dt` 积分出来的，和陀螺仪严格自洽，所以电脑端的 `e` 应该一直很小（不带 `--att-bias` 时 1~2°）。

电脑端应该先打印一次 `[ok] 旋转轴已锁定`，再依次打印出对应的 `↓ 按下 / ↑ 松开`、`[回正] 角度已归零`。

不想开两个终端就用现成的联调脚本（自动起停两端，只打印关键事件）：

```bash
python tools/check_freeaxis.py                 # 倾斜 30° + 自动轴，跑 20 秒
python tools/check_freeaxis.py --tilt 0 --axis z --seconds 10
```

## 数据格式（和手机端 `vw-udp` 插件一致，小端）

### 样本包 104 字节 `<ii7dii4d>`

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | int32 | type | 固定 1 |
| 4 | int32 | seq | 包序号，从 1 开始递增（算丢包用） |
| 8 | float64 | gx | 陀螺仪 x 轴角速度（rad/s） |
| 16 | float64 | gy | 陀螺仪 y 轴角速度 |
| 24 | float64 | gz | 陀螺仪 z 轴角速度 |
| 32 | float64 | ax | 加速度计 x 轴（单位 g） |
| 40 | float64 | ay | 加速度计 y 轴 |
| 48 | float64 | az | 加速度计 z 轴（手机平放时 ≈ 1.0） |
| 56 | float64 | t | 手机端采样时刻的毫秒时间戳（Unix epoch ms） |
| 64 | int32 | btnMask | 按键位图（见 `vwheel/protocol.py` 的 `BUTTON_CODES`） |
| 68 | int32 | flags | bit0=角度归零，bit1=重新校准 |
| 72 | float64 | qx | 姿态四元数 x（Android 旋转向量格式） |
| 80 | float64 | qy | 姿态四元数 y |
| 88 | float64 | qz | 姿态四元数 z |
| 96 | float64 | qw | 姿态四元数 w；**四个都 0 表示手机没有姿态数据** |

```python
type_, seq, gx, gy, gz, ax, ay, az, t, mask, flags, qx, qy, qz, qw = struct.unpack("<ii7dii4d", data)
```

### 配置包 36 字节 `<iii3d>`

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | int32 | type | 固定 2 |
| 4 | int32 | rangeDeg | 单边角度范围 90..900（`90` = ±90°，`900` = ±900°） |
| 8 | int32 | axis | 转向轴 0=X 1=Y 2=Z 3=自动识别 |
| 12 | float64 | deadzone | 死区 rad/s |
| 20 | float64 | smoothing | 平滑 0~0.95 |
| 28 | float64 | selfCenter | 自动回正速率 1/秒，0 = 关 |

为什么数值都用 double 而不是 float32：`t` 是 1.7e12 量级，float32 只有 24 位尾数，
在这个量级上步进约 131 秒，时间戳会被压成废数。104 字节 × 200Hz 也只有 20.8KB/s。

## 列的含义

| 列 | 含义 |
|----|------|
| `200.0pkt/s` | 最近约 1 秒的平均收包速率（手机端插件请求 200Hz，实际看设备给的频率） |
| `丢包=0` | 按 `seq` 缺口估算的累计丢包（局域网一般就是 0） |
| `±N°` | 当前的角度量程（单边，来自手机配置包或命令行 `--range`，90..900 无级） |
| `-----#----` | 转向条：中间是 `|`，`#` 是当前值在量程上的位置 |
| `角度` | 积分出来的转向角，单位度，正负表示方向 |
| `值` | **最终结果**：`角度/量程*32767`，范围 ±32767，就是以后的摇杆量 |
| `角速度` | 当前（去零偏、过死区、已平滑）的角速度，rad/s |
| `键` | 当前按住的按键，例如 `A` / `LB+RT` / `↑+→`，没按显示 `-` |
| `姿态=ok e=+0.4°` | 姿态慢修正的状态：`ok` = 有姿态参考，`e` = 姿态与积分的差；`姿态=-` 表示没有姿态数据 |
| `t=+1.52s` | 手机端时间戳换算成「距第一包多少秒」 |
| `<- ip:port` | 手机的地址，用来确认是不是手机发来的 |
| `已断流` | 超过 1 秒没收到包（手机切后台、锁屏、退出了都会这样） |

## 角度比实际小？按这个查

先加 `--raw`，状态行末尾会多出两段：

```
... 姿态=ok e= +2.8°  raw=(+0.01,+0.03,+0.06) 轴外=0.20x
```

`raw` 是手机原始三轴角速度，`轴外` 是「垂直于转向轴的分量 ÷ 沿轴的分量」，也就是轴错位角的正切：

| 轴外比 | 错位角 α | 角度缩水到 | 每 90° 少 |
|--------|----------|------------|-----------|
| < 0.10 | < 6° | ≥ 99.4% | < 0.5° |
| 0.15 | 8.5° | 98.9% | 1° |
| 0.35 | 19° | 94.4% | 5° |
| 0.50 | 27° | 89% | 10° |

按这个顺序排除（顺序就是可能性从高到低）：

1. **轴外比很大（> 0.3）** → 转向轴没对上。手机设置页把「转向轴」改成**自动**，或者按锁定时打印的
   `n=(x, y, z)` 看是不是和你预期的贴法一致（贴着盘面、屏幕朝上时应该接近 `(0, 0, 1)`）。
2. **停住不动，角度还在自己慢慢变小** → 设置页的「自动回正」不是 0。`0.1` 的速率在转 1 秒的情况下就会
   吃掉 8~9°。想让它回正就调小（0.05 以下），不想要就设 0。
3. **轴外比很小、但两个方向都均匀偏小** → 不是算法问题，是陀螺仪标度误差（手机出厂标定偏差，常见 2~5%，
   个别能到 10%）或者手机相对方向盘轻微打滑（绑带松了）。这两种都跟快慢无关：打满一个已知角度，量一下
   「读数 ÷ 真实角度」，用 `--gain` 的倒数补偿即可（比如读数只有 94%，就加 `--gain 1.06`）。

> 死区（`--deadzone`）和平滑（`--smoothing`）**不会**造成这种成比例的偏小：实测默认参数下 90° 的积分
> 误差只有 0.02~0.24°（< 0.3%），把两者都关掉也还是一样。

## 收不到数据？按顺序排查

1. **手机和电脑在同一个 Wi-Fi / 局域网**，且电脑的 IP 填对了（`main.py` 启动时会打印本机所有可用的局域网 IP）。
2. **Windows 防火墙**：第一次运行 python 时如果弹窗询问，一定要选「允许访问」。已经点过「取消」的话，去
   「Windows Defender 防火墙 → 允许应用通过防火墙」把 python 放开，或者临时用管理员 PowerShell 放行端口：
   ```powershell
   New-NetFirewallRule -DisplayName "virtual-wheel-udp" -Direction Inbound -Protocol UDP -LocalPort 8888 -Action Allow
   ```
3. **手机端真的在发**：手机页面上的「已发送」包数应该一直在涨；不涨就是陀螺仪或插件出错，看页面上的红字提示。
4. **端口一致**：手机设置页填的端口和 `main.py` 的端口必须一样。
5. 有些路由/AP 开了「客户端隔离（AP isolation）」，会禁止无线设备之间互相访问，这种情况换热点试试。

## 扩展点

映射规则集中在 `vwheel/gamepad.py` 的 `GamepadOut.update()`：

```python
pad.left_joystick_float(x_value_float=st.value / 32767.0, y_value_float=0.0)
pad.press_button(button=XUSB_BUTTON.XUSB_GAMEPAD_A)  # 按键边沿
```

要加新按键，只需在 `vwheel/protocol.py` 的 `BUTTON_CODES` / `BUTTON_ENUM` 里各加一行，
打印用的箭头文案放在 `BUTTON_LABELS`。
LT/RT 现在只有 0/1 两档，想做成模拟扳机需要在协议里再加字段（或者用按压力度估算）。
